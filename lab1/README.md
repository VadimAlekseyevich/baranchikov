# Лабораторная работа №1 — программа с данными в оперативной памяти

Вариант 1: **биржа валют**.

## Что реализовано

- Все состояние хранится только в оперативной памяти процесса.
- Пользователь работает с системой через Java-интерфейс `Exchange` — сетевого API в этой работе нет.
- Клиент может подключиться и отключиться, выставить лимитный ордер на покупку или продажу валютной пары.
- Ордер содержит количество валюты, потому что по условию требуется поддерживать частичное исполнение.
- Встречные заявки автоматически сопоставляются по правилу price-time priority:
  - для покупки сначала выбирается минимальная цена продажи;
  - для продажи сначала выбирается максимальная цена покупки;
  - при одинаковой цене раньше выставленный ордер имеет приоритет.
- Цена сделки равна цене уже находившегося в книге (resting) ордера.
- Поддерживается частичное и полное исполнение ордеров.
- При каждой сделке оба клиента получают `TradeNotification`.
- Если клиент offline, уведомление хранится в памяти и доставляется при следующем `connect`.
- Реализация потокобезопасна: несколько клиентов могут одновременно обращаться к одному экземпляру биржи из разных потоков.

Такое разделение оставляет публичный API независимым от способа хранения. В следующих лабораторных эту реализацию можно развивать, не привязывая тестовые сценарии к внутренним коллекциям.

## Основной сценарий

1. Покупатель подключается к бирже и выставляет BUY-ордер.
2. Продавец подключается и выставляет пересекающийся SELL-ордер.
3. Биржа создаёт сделку на минимальное из оставшихся количеств двух ордеров.
4. Оставшееся количество частично исполненного ордера остаётся в книге.
5. Оба участника получают уведомление о сделке.
6. Следующий встречный ордер может исполнить остаток.

Отдельный тест проверяет offline-сценарий: уведомление сохраняется после `disconnect` и передаётся после повторного `connect`.

## Запуск

Из каталога `lab1`:

```bash

```

Демонстрационный запуск:

```bash
mvn -q -DskipTests package
java -cp target/classes org.example.Main
```

Требуется JDK 23 и Maven 3.9+.

## Тесты

`InMemoryExchangeTest` проверяет:

- частичное и полное исполнение;
- формирование сделки;
- уведомления обоим участникам;
- сохранение уведомления offline-клиента и доставку после подключения;
- ценовой приоритет.

`InMemoryExchangeConcurrencyTest` запускает размещение встречных заявок из разных потоков через `ExecutorService` и синхронизирует одновременный старт через `CountDownLatch`.

## Ответ на контрольный вопрос

**Как производится имитация одновременной работы разных клиентов в тестах?**

Каждый клиентский запрос выполняется отдельной задачей в пуле потоков `ExecutorService`. `CountDownLatch` удерживает задачи до общего сигнала старта, после чего они одновременно вызывают методы одного экземпляра `Exchange`. Затем тест ожидает завершения всех `Future` и проверяет итоговое состояние: число сделок, суммарный объём и отсутствие незакрытых ордеров. Так моделируется требуемая работа разных клиентов в отдельных потоках одного процесса.
