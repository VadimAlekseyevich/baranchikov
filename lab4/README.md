# Лабораторная работа №4 — использование контейнеров

Лабораторная продолжает `lab3`.

По заданию необходимо:

- упаковать процессы в Docker-контейнеры;
- настроить взаимодействие между ними;
- сохранить H2-состояние при перезапуске;
- запускать тесты как из IDE, так и внутри отдельного Docker-контейнера.

Именно это реализовано в `lab4`, без изменения бизнес-логики предыдущей работы.

## Структура

Используются два контейнера:

```text
tests  -- UDP -->  exchange-server  -->  H2
                                  |
                                  v
                           Docker volume
```

- `exchange-server` — UDP-сервер из третьей лабораторной;
- `tests` — отдельный контейнер, запускающий JUnit;
- `exchange-data` — именованный Docker volume с файлом H2.

Оба контейнера собираются из одного `Dockerfile` и одного базового образа:

```text
maven:3.9-eclipse-temurin-25-alpine
```

Отдельный JRE-образ не используется: для лабораторной он не нужен.

## Почему нужен Docker-образ

Контейнер не использует установленную на Windows Java/Maven напрямую. Поэтому Docker один раз скачивает базовый образ с Linux, Java и Maven.

После первого успешного скачивания слои остаются в локальном Docker cache и повторно обычно не загружаются.

## Docker Compose

`exchange-server` запускает:

```text
org.example.Main /app/data/exchange 9000
```

UDP-порт публикуется как:

```text
9000:9000/udp
```

H2 хранится по пути:

```text
/app/data/exchange
```

Каталог `/app/data` подключён к named volume `exchange-data`, поэтому обычный restart контейнера не удаляет данные.

Тестовый контейнер обращается к серверу внутри Docker-сети по адресу:

```text
exchange-server:9000
```

## Тесты из IDE

Как обычный Maven-проект:

```bat
cd lab4
mvn test
```

Docker-специфичные тесты без переменных окружения автоматически пропускаются.

## Запуск в Docker

Из папки `lab4`:

```bat
docker compose build
docker compose up -d exchange-server
docker compose ps
docker compose run --rm tests
```

Последняя команда запускает тесты в отдельном Docker-контейнере, как требует задание.

## Проверка сохранения H2 после restart

Для Windows:

```bat
verify-persistence.cmd
```

Сценарий:

```text
1. создаётся чистый volume;
2. запускается exchange-server;
3. test-контейнер записывает ордер через UDP;
4. exchange-server перезапускается;
5. test-контейнер проверяет, что ордер сохранился.
```

Таким образом проверяется требование о переживании перезапуска.

## Остановка

Остановить контейнеры, сохранив H2 volume:

```bat
docker compose down
```

Удалить контейнеры вместе с тестовыми данными:

```bat
docker compose down -v
```
